## Agenda

 - Leon provided an introduction to the Mainframe Software Hub for Linux: How do we provide a centralized place for providing s390x binaries for packages that aren’t currently packaged in any other ways (via a distribution, directly from upstream, etc.)?

 - Currently IBM provides build instructions for open source software, but are unable to provide binaries: https://github.com/linux-on-ibm-z/docs/wiki

 - Rishi explained that we want a fully open source platform for contributors to produce their binaries and host them for public consumption. He shared a proposed Architecture Diagram with a simplified view into what we might want to create, which included an Orchestrator, Configuration, Builders, Utilities, and a Logger.

 - Rishi asked about the path forward for getting access to infrastructure, and Elizabeth shared that she had put together a funding request document for the Software Discovery Tool and will share that with the team to see if it can be used as a template for the information the Open Mainframe Project if we decide we need paid resources.

 - Rohan expressed agreement with the workflow proposal and mentioned that GitHub workflow tooling might be helpful here, and provided a demo of how a workflow file works along with a GitHub API.

 - GitHub Actions are not available for s390x directly from GitHub, but you can cross-compile and IBM has recently launched a GitHub Actions service, but the infrastructure is still new and not ready to on-board projects at a large scale. We can also use GitHub Actions to farm out workloads to other types of builders.

 - Rishi noted that we could even host the binaries on GitHub through the releases process.

 - Elizabeth mentioned the process the zopen Community uses with a separate project for each z/OS port: https://github.com/zopencommunity and they also do their releases through that.

 - There was consensus that we want to use a similar process to zopen Community, with our own organization and then each project that is built by the project having their own repository.

 - Rishi will come up with a proposal for which project(s) to start with.

 - Rohan brought up prevention of malicious code, and Elizabeth mentioned we'd have to develop a mechanism to trust community members, and require PR reviews. He also mentioned SBOMs and security scorecards, which we agreed were all good things to keep in mind as our project grows.
